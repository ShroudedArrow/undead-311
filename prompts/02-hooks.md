# 02 — Create hooks with Kiro (ask in chat; Kiro writes .kiro/hooks/*.json in the current v1 schema)

Ask: "Create these hooks in .kiro/hooks/ using the current hooks schema, then list them and confirm each is recognized."

1. **kiro-log** — trigger: Stop. Action: a **command** (not an agent prompt) that appends date, surface, and a short changed-files summary to docs/KIRO_LOG.md. Agent-prompt hooks spend credits every time they fire, and a workflow fires Stop once per step. Add the narrative line yourself, or have the workflow's report step write one line per run.
2. **test-on-save** — trigger: PostFileSave, matcher for `pipeline/**/*.py` and `web/src/**/*.{ts,tsx}`. Action: command that runs the fast test subset for the changed area (`make test-fast`).
3. **data-validate** — trigger: PostFileCreate, matcher `data/raw/**`. Action: agent prompt "Run the data-steward checks on the new file and report schema drift."
4. **detector-revalidate** — trigger: PostFileSave, matcher `pipeline/undead311/detect/**`. Action: command `make validate` (re-scores the hand-labeled validation sample and updates docs/VALIDATION.md).
5. **coroner-eval** — trigger: PostFileSave, matcher `data/labels/coroner_labels.csv`. Action: command `make coroner-eval` (accuracy vs. 200 hand labels).
6. **copy-lint** — trigger: PostFileSave, matcher `web/src/**`, `docs/**`, `README.md`, `drafts/**`. Action: command `make copy-lint`, a small script (ask Kiro to write it) that flags banned words/patterns from voice.md, banned CSS defaults from design-system.md (gradients, uppercase+letter-spacing labels, '→' in button text), and counts TODO-COPY markers.
7. **channel-status** — trigger: PostTaskExec. Action: command `uv run python scripts/channel_post.py` (ask Kiro to write it with Python's standard library only, calling the GitHub REST API with `GITHUB_CHANNEL_TOKEN`; no `gh` needed, since it may not exist in a cloud sandbox). It reads the task details from the hook's stdin JSON and posts a one-line status comment to the current run-log issue in `ShroudedArrow/undead-311-ops` (issue number from the run directory's `channel.json`). It must ALWAYS exit 0, so a GitHub outage can never fail a task. Command hooks cost no credits; agents post only substantive messages.
8. **kill-switch** — trigger: PreTaskExec (and PreToolUse for shell). Action: a Python script (`uv run python scripts/kill_switch.py`) that exits non-zero (blocking) if `.kiro/STOP` exists in the working tree, OR if `ShroudedArrow/undead-311-ops` has an open issue labeled `stop` (checked with Python's standard library against the GitHub REST API; no `gh` dependency). If GitHub can't be reached, it allows the step (fail-open), so an outage can't stall the run. To halt a run from your phone: open an issue labeled `stop` in the channel repo.
9. **guard** — trigger: PreToolUse on shell commands. Action: command script that exits non-zero (blocking) for destructive commands: `rm -rf` anywhere in the repo or `$DATA_DIR`, `git push --force`, and edits to `.kiro/steering/**`, `.kiro/settings/**`, `.kiro/hooks/**`, `.kiro/agents/**`, `.kiro/STOP` (humans only), and `pipeline/tests/fixtures/expected_zombies.json` from workflow steps. It must ALLOW `.kiro/workflow-runs/**` (workflow artifacts) and task checkbox updates in `.kiro/specs/**/tasks.md`, or workflows will break.

**During big workflow runs:** set `enabled: false` on test-on-save, data-validate, and copy-lint. The workflow's own validate gates run the tests; per-save hooks would just slow every step and spend credits.
